# p018 redact_url param 值内嵌相对 query 不递归

- 现象：启用 `redact_data` 与 `redact_url_query` 时，期望 URL 任意层 query 中敏感键值均不出现明文；实际 `redact_url` 只识别顶层敏感键，非敏感参数值内嵌 query 会漏脱敏并返回 `url_status: 'captured'`。最小复现已确认两条分支均泄露：① 手动分支的 bare query、path-relative、root-relative、query-relative、protocol-relative 外层，如 `?next=child?token=secret`、`/outer?next=/child?token=secret`；② `new URL` 成功的 absolute/base-resolved 外层，如 `https://outer.example/start?next=child?token=secret`，且内嵌 absolute URL 也同样泄露。plain 与 `%3F`/`%3D` 编码内嵌值均可复现；Logger 包装入口输出同样保留 secret。该缺陷不是回归：t100 前版本已不递归 absolute 外层参数值且相对 URL 整体 fail-open，t100 只补了手动分支中 raw `scheme://` 值。
- 影响：敏感 query 可进入本地采集记录、应用日志、导出及 MCP 查询结果。已确认当前运行入口共 10 处：`src/extension/content/form_submit_capture.ts:61`（`form.action` 经 document base 解析为 absolute）、`src/extension/background/network_capture.ts:254`/`:338`/`:717`（WebSocket connection/frame/error）、`:814`（CDP body event）、`:872`（webRequest）、`:985`（CDP primary）、`src/shared/logger.ts:36`（message/details/Error stack 中 arbitrary absolute/path/relative/bare-query 子串）、`src/bridge/cdp_handler.ts:251`/`:288`（external CDP response/request）。另确认 8 处同因调用当前不在运行主链：`src/extension/background/webrequest_handler.ts:47`、`src/extension/background/cdp_handler.ts:532`/`:571`/`:655`/`:692`/`:858`、`src/extension/background/network_webrequest.ts:142`（未调用 handler factory）、`src/extension/background/service_worker.ts:816`（`network_body_hook` 路由与 content 现发事件类型不一致，当前不可达）；若后续重新接线，同样继承缺陷。
- 根因：产品缺陷（隐私/安全脱敏机制不完整）。`src/shared/redaction.ts:61-80` 的 absolute 分支仅遍历 `parsed.searchParams` 顶层 key，从不检查非敏感 key 的 value；`:81-116` 的手动分支虽然遍历 param value，但递归门槛 `URL_SUBSTRING_RE`（`:14`、`:107`）只匹配 raw `scheme://`，不会匹配 path/root/query/protocol-relative 值，也不会匹配 percent-encoded nested query。`src/shared/logger.ts:33-36` 只截取外层 URL/query 后委托同一 helper，不能补偿。全仓同类扫描检索轴：`redact_url(`、`redact_url_query`、`URL_SUBSTRING_RE`、`URL_SUBSTRING_PATTERN`、`SENSITIVE_URL_PARAM_PATTERNS`、`searchParams`、`[REDACTED]`，并沿 import/call graph 区分运行与 dormant 路径；共找到 20 个 `src` 命中（helper 声明与内部递归 2，外部调用 18），未发现第二套独立 URL query 脱敏实现，已确认位点即“影响”清单，无待确认位点。
- 测试缺口：现有相关 7 个测试文件共 168 项全部通过但复现仍泄露。`redaction.test.ts`、`network_capture.test.ts`、`logger.test.ts`、`cdp_handler_redaction.test.ts`、`websocket_capture.test.ts` 只测顶层敏感 key；`logger_stack_redact.test.ts` 只补了顶层 relative query 与“手动外层 + 内嵌 absolute URL”，未覆盖“非敏感外层 key + 内嵌 relative query”或 absolute/base-resolved 外层；`form_submit_capture.test.ts` 的 `next=/home` 不含内层 query。补测方向：① helper 表驱动交叉覆盖 outer absolute/base-resolved、path-relative、root-relative、bare/query-relative 与 nested absolute/path/root/query/protocol-relative、plain/encoded，逐例断言 secret 消失、占位存在、非敏感结构保留、`url_status` 与实际改写一致；② Logger message/details/Error stack 覆盖 relative nested 与 absolute outer nested；③ 对运行入口逐族做接线回归：form base-resolved action，extension CDP primary/body、webRequest、WS connection/frame/error，external bridge request-only 与 response-only（现有 bridge 测试 request 先到使 response 新建分支未执行）；④ retained dormant handler 各补直调，或后续删除 dormant 路径时同步删除对应补测；⑤ 对最终存储/输出对象断言无明文，防调用方仅把 `url_status` 写成 `redacted` 而 URL 仍泄露。
