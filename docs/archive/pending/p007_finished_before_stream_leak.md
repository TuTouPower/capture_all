# p007 finished_before_stream 生命周期标记泄漏

- 现象：期望 `finished_before_stream` 只在 `Network.loadingFinished` 早于 `Network.responseReceived` 的竞态窗口暂存 `req_key`，请求完成或最终输出后立即删除。实际生产路径 `src/extension/background/network_capture.ts` 在每次 `loadingFinished` 无条件 `add(req_key)`；正常时序为 `responseReceived` 先到，唯一消费式 `delete` 已经错过，随后普通响应、SSE 响应及 body 获取失败路径完成 emit 后均不删除。最小复现中 25 个普通请求完成并 emit 后 Set size 为 25，单个 SSE 完成后对应 key 仍存在，直到停止采集才由 `clear()` 释放。
- 影响：启用 CDP response body capture 的主 target 与子 session 均受影响；普通 Document/XHR/Fetch 与 SSE 完成请求按数量线性累积复合键，长采集或高请求量页面持续占用 MV3 Service Worker 内存。残留 key 若在同一 session 内遇到 requestId 复用，还会让后续 SSE 被误判为“已完成后才识别流式”，跳过 `Network.streamResourceContent` 并降级为 partial。缺失 request metadata 的边缘事件也会残留标记。
- 根因：分类为产品缺陷 + 测试假绿。共享机制是“竞态标记在终态事件无条件创建，但生命周期清理未覆盖全部终态/早退路径”，并叠加同一 CDP handler 的重复实现漂移：T023 仅修复并测试 `src/extension/background/cdp_handler.ts` 常规有 metadata 路径，实际监听器仍走 `network_capture.ts` 内联 `handle_cdp_event`，生产实现未同步。全仓同类扫描已完成，检索轴包括精确符号 `finished_before_stream`、全部 `Network.loadingFinished` handler、request-keyed Set/Map 的 `add/set/delete/clear`、`network_capture.ts` 与 `cdp_handler.ts` 对称分支。
    - 已确认位点 1：`src/extension/background/network_capture.ts` 的 `handle_cdp_event`、`try_resolve_deferred`、`schedule_orphan_check`。普通 body resolve/reject、SSE emit、deferred/orphan 清理与早退均未删除标记；这是当前生产路径。
    - 已确认位点 2：`src/extension/background/cdp_handler.ts` 的 `handle_loading_finished`、`schedule_orphan_check`。常规有 metadata 路径已删除，但无 metadata、`capture_response_body=false` 早退，以及 orphan 无 consumer/无 body 早退仍保留标记；当前无生产调用，但属同因复制实现。
    - 已排除：`src/bridge/cdp_handler.ts` 不使用该竞态标记；`src/extension/background/network_context.ts` 只声明并在 reset 清空集合，没有写入位点；p006 `cdp_primary_emitted` 是只写死集合，症状相似但语义与修复策略不同，继续独立处理。
- 测试缺口：`tests/unit/cdp_state_cleanup.test.ts` 直接调用已修过的 `cdp_handler.handle_cdp_event`，只覆盖有 metadata 的普通成功路径，未触达生产 `network_capture.ts`；因此 100 请求清零断言是假绿替身。`network_cdp.test.ts`、`network_capture_session_key.test.ts`、`sse_body_cap.test.ts` 虽触达生产逻辑，只断言事件、命令 target 或 body 状态，不断言终态集合；session-key 测试还在每例前主动 clear 集合，且 SSE 场景未发送 `loadingFinished`。E2E streaming 用例没有结果断言。补测应在生产 `network_capture` 层覆盖普通成功、`getResponseBody` reject、SSE 完成、`loadingFinished` 先于 `responseReceived`、无 metadata/orphan 早退，以及 root/子 session；逐场景断言 marker 只在竞态窗口存在、所有终态后为 0，并加 100 请求有界性回归。对已确认位点 2 补无 metadata/早退断言；若后续消除重复实现，则改为断言生产入口唯一调用共享 handler。
